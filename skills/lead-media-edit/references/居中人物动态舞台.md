# 居中人物动态舞台（full-video-motion-workflow 适配层）

当用户要求“人物在中央，周围弹出卡片/文字/图形，并且跟着口播同步”时，使用 `stage` 人物状态。它和原来的 `pip` 状态不同：

- `pip`：人物缩成圆环，画面让位给完整 B-roll。
- `stage`：人物保留原始全屏位置和肢体动作，动效作为透明层叠在人物周围；人物与动效在同一条口播时间线上编排。

## 接入方式

1. 先按 `full-video-motion-workflow` 生成 `scene-plan.json`、`STORYBOARD.md` 和 `style-tokens.json`，按视觉段落写进入、稳定态、更新和退出。
2. 在 `lead-media-edit` 的粗剪结果上继续使用 `transcript_rough.json` 的字级时间，不要用原片时间轴猜卡点。
3. 可以先用候选生成器扫描数字、步骤、工具名和“问题/关键/注意”等语义触发词：

```bash
python <lead-media-edit>/scripts/build_motion_cues.py \
  工作素材/transcript_rough.json \
  .code/<项目名>/motion/src/data/motion-cues.json
```

生成的文件必须人工复核：删除没有解释作用的卡片，合并相邻重复 cue，补充截图或真实数据，再进入 Remotion。候选生成器只负责找时间点，不会替你决定画面内容。

复核后在打包前运行结构校验：

```bash
python <lead-media-edit>/scripts/validate_motion_cues.py \
  .code/<项目名>/motion/src/data/motion-cues.json \
  --duration <粗剪时长> \
  --public .code/<项目名>/motion/public
```

它会检查时间范围、重叠密度、类型字段、步骤/数字必填项和本地截图引用；校验失败时不要继续渲染。

素材较多时，先生成清单，避免把不存在或不透明的文件误当成叠加层：

```bash
python <lead-media-edit>/scripts/build_asset_manifest.py \
  .code/<项目名>/motion/public \
  .code/<项目名>/motion/asset-manifest.json
```

如果人物会明显左右移动，可额外维护一个 `face-boxes.json`：

```json
{
  "boxes": [
    {"start": 0, "end": 12.4, "x": 846, "y": 178, "w": 230, "h": 410},
    {"start": 12.4, "end": 28.0, "x": 904, "y": 198, "w": 250, "h": 430}
  ]
}
```

再把 `--face-boxes face-boxes.json` 传给校验器；它会把脸部框扩大后检查卡片是否压脸。没有可用检测器时，先用抽帧人工标两到四个区间，可靠性高于凭感觉移动卡片。

需要让人物在 `pip` 缩放时也跟随镜头移动，可把相同区间换成 `project.ts` 中的 `FACE` 关键帧：

```ts
export const FACE = [
  { t: 0, x: 960, y: 470, r: 300 },
  { t: 12.4, x: 1010, y: 455, r: 286 },
  { t: 28.0, x: 920, y: 482, r: 310 },
];
```

Presenter 会在关键帧之间平滑插值；不提供关键帧时继续使用固定 `FACE`。

4. 在 `motion-template/src/project.ts` 里把需要居中人物的段落写成：

```ts
export const MODES: Mode[] = [
  { t: 0, mode: "full" },
  { t: 3.2, mode: "stage", dur: 0.42 },
  { t: 8.6, mode: "pip", dur: 0.62 },
  { t: 12.4, mode: "full", dur: 0.62 },
];
```

`stage` 会让 Presenter 保持全屏，而把场景动效放在人物上层；`pip` 仍按旧逻辑缩到圆环。这样可以在一条片里交替使用“人物主讲 + 周围解释动画”和“人物缩小 + 大面积 B-roll”。

## 动效卡点契约

每个段落把动效写成独立 cue，建议放在 `.code/<项目名>/motion/src/data/motion-cues.json`：

```json
[
  {
    "id": "workflow-card-01",
    "start": 3.18,
    "duration": 2.4,
    "anchor": "关键词起音前 0.08 秒",
    "kind": "feature-card",
    "side": "left",
    "title": "先收集信息",
    "body": "把资料变成自己的理解",
    "enter": "slide-out-expo",
    "hold": "subtle-float",
    "exit": "fade-out-cubic",
    "sfx": "pop"
  }
]
```

规则：一个 cue 只表达一个新信息；卡片先入场、停留至少 0.5 秒，再退出；动画开始时间取关键词字时间前 0–0.15 秒；同一瞬间最多一个主卡片和两个辅助标签。

需要把信息明确指向人物手势、手机或画面中的某个位置时，可使用 `callout` cue，并设置 `target: {x, y}`。连线只承担指向关系，主信息仍放在左右安全区。

## 人物安全区

默认 1920×1080 横屏时，人物头脸和手势区域属于动态禁区。卡片优先放在左上、右上和画面两侧，避免覆盖脸、嘴、手和底部字幕带。若人物明显偏移，先抽帧确认 `FACE`，再把 `FACE` 或场景局部禁区写进计划；不要为了塞卡片把人物硬挪到角落。

## 与现有交付链的关系

- `lead-media-edit` 继续负责粗剪、Whisper、字幕、音效混音、最终合成与 QA。
- `full-video-motion-workflow` 负责整片视觉段落、透明动效拆分和转场策略。
- HyperFrames 适合网页/流程/UI 互动；Remotion 适合人物状态、标题、卡片、数字和跨段落同步。
- 透明动效单独输出 WebM VP9/ProRes 4444；只有全屏不透明 B-roll 使用 H.264 MP4。

这样同一个口播视频可以先用 `stage` 把人物与动画编排在一起，再在需要解释复杂画面时切换 `pip`，不需要改变原有字幕和音频验收链。
